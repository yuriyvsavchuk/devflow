# Getting Access to Devflow Team

The `devflow-team` repository is private. Access is granted individually to collaborators who are using or evaluating the team extension in a professional context.

---

## Before You Request Access

Make sure you have the individual Devflow framework installed and working:

- Repository: [github.com/yuriyvsavchuk/devflow](https://github.com/yuriyvsavchuk/devflow)
- The team extension is built on top of the individual framework — it requires the base installation

Review the [README.md](README.md) in this directory to confirm the team extension addresses your team's situation.

---

## How to Request Access

Open a GitHub issue in the public [devflow](https://github.com/yuriyvsavchuk/devflow) repository using the title:

```
[Team Access Request] <your name or organization>
```

Include the following in the issue body:

- **Your GitHub username** — the account that will need repository access
- **Context** — a brief description of your team or project (size, stack, current process)
- **What you are trying to solve** — which of the team extension's capabilities you are most interested in
- **Any questions** — anything you want to clarify before getting started

---

## What Happens Next

Access requests are reviewed manually. You will receive a response on the GitHub issue within a few business days.

If access is granted, you will receive:

1. A collaborator invitation to the `devflow-team` private repository
2. The `USER-MANUAL-TEAM.md` — the full team framework manual with installation instructions, pipeline reference, and examples
3. An invitation to provide feedback as you adopt the framework

---

## Questions

If you have questions before requesting access, open an issue in the public [devflow](https://github.com/yuriyvsavchuk/devflow/issues) repository with the title prefix `[Question]`. General questions about Devflow, the team extension, or AI-assisted development workflows are welcome there.
